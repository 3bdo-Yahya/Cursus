# S3-005 Bug Audit Report

## Scope

Audit of the completed S3-005 flow:

- S3-005a: OpenAI advisor service/client
- S3-005b: advisor controller action and dynamic student context
- S3-005c: JavaScript chat client calling the server endpoint

## Findings

### 1. Advisor UI still showed hardcoded seeded student details

Severity: Medium

The AI Advisor empty state still displayed `Ahmed Kamal`, `CS - Year 3 - CGPA 3.24`, and `Good Standing`.

Why it mattered:

- The backend now builds context from the authenticated student's graduation audit.
- Static profile chips could mislead users into thinking the advisor is using another student's data.

Fix:

- Replaced hardcoded student-specific chips with generic profile-aware labels:
  - `Your profile`
  - `Graduation audit`
  - `Standing and GPA`

### 2. Advisor JS used a root-relative endpoint

Severity: Low

The chat client called `/Student/AiAdvisorChat` directly.

Why it mattered:

- This works at the site root, but can break if the application is deployed under a path base or virtual directory.

Fix:

- Added `data-advisor-chat-url="@Url.Action("AiAdvisorChat", "Student")"` to the Razor page.
- Updated the JavaScript client to read the endpoint from the rendered page.
- Kept `/Student/AiAdvisorChat` only as a fallback.

### 3. Non-JSON error responses could be rendered into the warning banner

Severity: Medium

If the request failed with a login page, HTML error page, expired session response, or malformed JSON, the client could display raw response text in the warning fallback.

Why it mattered:

- Session expiration or antiforgery failures often return HTML instead of JSON.
- Rendering huge escaped HTML inside the chat warning would be confusing and unprofessional.

Fix:

- Added generic fallback messages for non-JSON responses.
- Added special handling for `401`, `403`, redirects, `400`, and `5xx` responses.
- Added message normalization and length limiting.
- Added defensive handling for malformed JSON responses.

### 4. User chat avatar was hardcoded to `AK`

Severity: Low

User message bubbles showed `AK`, which was another seeded-profile artifact.

Why it mattered:

- The advisor page is shared by all authenticated students.
- The UI should not show initials for a specific seeded account.

Fix:

- Replaced the hardcoded initials with a generic `You` avatar label.

The S3-005 flow is now more robust end-to-end:

- The UI no longer shows hardcoded seeded student profile details.
- The JavaScript endpoint is generated by MVC routing.
- The fallback warning handles server, auth, antiforgery, malformed JSON, and OpenAI failure responses cleanly.
- The backend service/controller/prompt flow remains unchanged and covered by existing tests.
